## 问题

在个人网站的线索采集流程中，表单提交不仅需要保存用户填写的业务信息，也可以保留 GA4 使用的匿名客户端标识，为后续分析访客行为与线索之间的关系提供数据基础。

本项目希望解决三个问题：

- 如何从浏览器中获取 GA4 Client ID，并将其纳入表单提交数据？
- 如何将该标识与其他表单字段一起传递到后端，并持久化保存？
- 如何验证 GA4 事件采集与线索记录中的标识数据？

## 做法

### 1. 通过 JavaScript 读取 `_ga` Cookie

编写 JavaScript，从浏览器的 `_ga` Cookie 中读取并解析 Client ID。

由于该值需要进入表单提交数据，而不只是作为页面上的临时变量使用，因此将提取逻辑放在表单数据准备阶段，让标识能够随业务字段一起提交。

实现时需要考虑 Cookie 缺失、读取失败和格式变化等情况，避免分析标识不可用时影响正常的表单提交。

### 2. 使用表单隐藏字段传递 Client ID

网站表单由 AI 辅助开发，并部署在自己的个人网站中。

将读取到的 Client ID 写入表单隐藏字段，使其能够与用户填写的其他字段一起提交。访客无需手动填写，也不需要改变正常的表单交互流程。

这种设计将浏览器端的分析标识纳入现有的数据传输链路，而不需要为采集标识单独增加一个用户操作步骤。

### 3. 通过 Cloudflare Worker 接收并保存线索

表单数据提交至 Cloudflare Worker，由后端处理并保存。

线索数据采用双备份方式持久化。实施后，已经能够在实际的线索记录中查看到 Client ID，验证了该字段成功从浏览器端传递至后端存储。

这一环节完成了匿名客户端标识从浏览器环境到线索数据层的传递。

### 4. 使用 GTM 与 GA4 验证事件采集

GA4 事件采集采用另一条独立路径：通过 GTM 原生内置的 Client ID 变量获取标识，并将其作为表单提交事件的自定义参数发送至 GA4。

在 GA4 DebugView 中检查表单提交事件及相关参数，确认事件采集链路正常工作。

这里需要区分两件事：表单中的隐藏字段负责将 Client ID 传递给后端；GTM 内置变量负责向 GA4 事件提供 Client ID。两条路径分别满足线索数据保存和事件数据采集的需求。

## 结果

本项目已经完成并验证的成果包括：

- 使用 JavaScript 读取并解析浏览器中的 `_ga` Cookie。
- 将 Client ID 写入表单隐藏字段，并随表单数据提交。
- 通过 Cloudflare Worker 接收表单数据，并将 Client ID 保存到线索记录中。
- 通过 GTM 内置变量将 Client ID 作为自定义参数发送至 GA4。
- 在 GA4 DebugView 中确认表单提交事件及相关参数，并在实际线索记录中确认 Client ID 已保存。

本阶段实现的是浏览器端标识采集与线索数据持久化，并验证了 GA4 事件采集。尚未实施 GA4 BigQuery Export 与线索记录的关联分析，也未验证该数据链路对线索质量、商机转化率或收入的影响。

## 学到

### 1. 采集到一个标识，不等于完成了身份关联

Client ID 可以作为连接浏览器行为与线索记录的候选标识，但它本身并不自动完成两个系统的数据关联。实际分析还需要确认两端的标识一致，并处理 Cookie 缺失、浏览器变化和重复提交等情况。

### 2. GA4 原生身份标识与自定义参数有不同用途

GA4 原生 Client ID 参与客户端识别；将其作为自定义事件参数发送，则是为了让这个值能够作为事件数据被采集。

自定义维度的 Scope 决定数据如何用于报告分析，并不会改变 GA4 原本的身份识别机制。因此，不需要仅仅为了采集 Client ID 就将它注册为高基数自定义维度。

### 3. 为后续的跨系统行为分析保留数据基础

后续可以接入 GA4 BigQuery Export，利用导出事件中的 `user_pseudo_id`、`ga_session_id` 和事件时间等字段，与线索记录中的 Client ID 及提交时间进行匹配。

在验证关联规则后，可以进一步分析线索提交前的访问路径、内容互动和来源渠道，并将行为特征与 CRM 中的线索质量及商机结果结合。

这部分属于下一阶段的实施方向，而非本项目已经完成的成果。

**本项目的核心价值，是将 GA4 客户端标识从浏览器端带入线索数据层，并验证了独立的 GA4 事件采集路径，为后续关联网站行为与线索记录建立了技术基础。**
